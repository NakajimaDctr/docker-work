この会話で直前に行われた実質的な質疑応答を、対応する `docs/<章>/notes.md` に、
このリポジトリで既に使われている形式のまま追記する
(参考: `docs/01-containers-and-images/notes.md`, `docs/03-dockerfile-basics/notes.md`)。

## 1. 対象の章を決定する

1. `$ARGUMENTS` が空でなければ、それを章のディレクトリ名(例: `03-dockerfile-basics`)として扱い、
   `docs/<その名前>/` を直接使う。
2. 指定がなければ、この会話中のコンテキスト(`ide_opened_file`、`ide_selection`、
   または会話中で言及されたファイルパス)から `exercises/NN-xxx/...` や
   `docs/NN-xxx/...` のようなパスを探し、先頭の番号 `NN` を抽出して
   対応する `docs/NN-*/` ディレクトリを特定する(`ls docs/` や `Glob` で正式名を確認する)。
3. どちらからも確信の持てる対象が得られない場合は、何も書き込む前に
   ユーザーにどの章に記載するか確認する。

## 2. `notes.md` を特定または新規作成する

対象ファイル: `docs/<章>/notes.md`

既に存在する場合は、まず全文を読む(上書きではなく挿入するため)。

まだ存在しない場合は新規作成する。`docs/<章>/README.md` の1行目は必ず
`# NN. タイトル` の形式(例: `# 03. Dockerfileの基本`)になっているので、
そこから `NN` と `タイトル` を抽出し、以下の内容でファイルを作成する。

```
# 学習メモ・QA集

このファイルは、NN章「タイトル」を学習する中で出た疑問と回答をQA形式でまとめたメモです。

---

<手順3で作る新規エントリをここに挿入>

前へ: [README](README.md)
```

## 3. 新規エントリを整形する

- **質問**: この会話でのユーザーの実質的な質問を、`?`で終わる簡潔な一文にまとめる。
  「教えて」「詳しく」などの付随語は取り除き、本質的な問いだけを残す。
- **回答**: この会話で実際に行った回答の要点を、このリポジトリの既存notes.mdの
  文体(短い説明文、列挙は箇条書き、コマンド/設定例は言語タグ付きコードブロック
  ` ```dockerfile ` など)に合わせて書き直す。概念の理解に本当に役立つ場合のみ
  ` ```mermaid ` 図を使う(参考: `docs/01-containers-and-images/notes.md`)。
  図やコードブロックは、文章だけで十分な場合には無理に入れない。

エントリのテンプレート:

```
## Q. <質問>?

**A.**
<回答本文>

---
```

このブロックを、ファイル末尾の`前へ: [README](README.md)`という行の直前
(＝現在の末尾にある`---`の直後)に挿入する。この新規エントリを含め、各エントリは
必ず1つの`---`で終わり、次のエントリまたはfooterへと続く。区切りの`---`を
重複させたり、footerの後ろに`---`を追加したりしない。

既存のエントリの内容・表現・順序は一切変更しない。

挿入前に、実質的に同じ質問のエントリが既にファイル内に存在しないか確認する。
存在する場合は重複追加せず、既に記録済みであることをユーザーに伝え、
追加または更新が必要か確認する。

## 4. 完了報告

書き込んだファイルパス(新規作成か追記かも明示)と、追加した
`## Q. ...` の見出しをユーザーに報告し、正しい章に反映されたか
すぐ確認できるようにする。
