# 03. Dockerfileの基本

## この章で学ぶこと

- `Dockerfile` を書いて、自分専用のイメージをビルドできるようになる
- 主要な命令(`FROM`, `COPY`, `RUN`, `CMD` など)の役割を理解する
- ビルドしたイメージからコンテナを起動して動作確認する

## 概念解説

これまでは `nginx` など、他の人が作った既製のイメージを使ってきました。ここからは自分でイメージを作ります。イメージの「作り方の設計図」となるのが `Dockerfile` というテキストファイルです。

主な命令:

| 命令 | 役割 |
|---|---|
| `FROM` | ベースになるイメージを指定する(必ず最初に書く) |
| `WORKDIR` | コンテナ内の作業ディレクトリを指定する |
| `COPY` | ホスト(自分のPC)のファイルをイメージにコピーする |
| `RUN` | イメージのビルド時に実行するコマンド(パッケージのインストールなど) |
| `CMD` | コンテナ起動時に実行するデフォルトのコマンド |
| `EXPOSE` | コンテナが使うポート番号を明示する(ドキュメント目的、実際のポート公開は`-p`で行う) |

`RUN` は「ビルド時」に一度だけ実行され、その結果がイメージに焼き込まれます。一方 `CMD` は「コンテナ起動時」に毎回実行されるという違いに注意してください。

## ハンズオン手順

`exercises/03-dockerfile-basics/` に移動します。

```bash
cd exercises/03-dockerfile-basics
```

このディレクトリには以下のファイルがあります。

- `hello.py`: 標準出力にメッセージを表示するだけの簡単なPythonスクリプト
- `Dockerfile`: `hello.py` をコンテナ化するための設計図

### 1. Dockerfileの中身を確認する

```bash
cat Dockerfile
```

### 2. イメージをビルドする

```bash
docker build -t my-hello-app .
```

- `-t my-hello-app`: イメージに名前(タグ)をつける
- `.`: Dockerfileがあるディレクトリ(ビルドコンテキスト)を指定。カレントディレクトリを意味する

ビルドログに、Dockerfileの各命令が1ステップずつ実行されていく様子が表示されます。

### 3. ビルドされたイメージを確認する

```bash
docker images | grep my-hello-app
```

### 4. コンテナとして実行する

```bash
docker run --rm my-hello-app
```

`--rm` をつけると、コンテナが終了すると同時に自動的に削除されます(使い捨てのコマンド実行に便利です)。`hello.py` の出力メッセージがターミナルに表示されれば成功です。

### 5. hello.pyを書き換えて再ビルドしてみる

`hello.py` のメッセージを好きな文言に変更し、再度ビルド・実行してみましょう。

```bash
docker build -t my-hello-app .
docker run --rm my-hello-app
```

変更後のメッセージが表示されることを確認してください。これにより「コードを変更したら再ビルドが必要」ということを体感できます。

## 確認問題・やってみよう

1. `RUN` と `CMD` の違いを自分の言葉で説明してみましょう。
2. `Dockerfile` の `FROM python:3.12-slim` の行を削除するとどうなるか(実際にはやらなくてOKですが、なぜ必須なのか)を考えてみましょう。
3. `docker build` を2回連続で実行し、2回目のビルドの方が速いことに気づけるか確認してみましょう。速くなるのは「レイヤーのキャッシュ」が効いているためです。どのレイヤーがキャッシュされ、どのレイヤーが再実行されたか、ビルドログから読み取ってみましょう。

## 詰まりやすいポイント・トラブルシューティング

- **`docker build` が `Dockerfile`を見つけられない**: `docker build -t 名前 .` の `.` は「カレントディレクトリにDockerfileがある」ことを前提にしています。正しいディレクトリで実行しているか `pwd` で確認してください。
- **コードを変更したのに実行結果が変わらない**: 再ビルド(`docker build`)を忘れている可能性が高いです。イメージは一度ビルドすると固定されるため、コード変更後は必ず再ビルドが必要です。
- **ビルドが毎回全ステップやり直しになる**: `COPY`をベースイメージのインストール処理より前に書くと、コードを1行変えるだけで以降の全レイヤー(パッケージインストール等)がキャッシュされず毎回やり直しになります。一般的には「変更頻度が低いもの(依存関係のインストール)を先に、変更頻度が高いもの(アプリコード)を後に」書くのがコツです(07章で実践します)。
