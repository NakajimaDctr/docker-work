# 05. ネットワーキング

## この章で学ぶこと

- コンテナ同士がどうやって通信するかを理解する
- Dockerの「ユーザー定義ネットワーク」を作成し、コンテナ名で名前解決できることを体感する
- ポート公開(`-p`)の仕組みをもう一段深く理解する

## 概念解説

これまで `-p 8080:80` でホストからコンテナにアクセスする方法を扱ってきましたが、コンテナ同士が通信する場合はどうなるでしょうか。

Dockerでは「ネットワーク」という仮想的なネットワーク空間を作成でき、同じネットワークに参加しているコンテナ同士は、IPアドレスを意識せずに **コンテナ名で** 相手を見つけて通信できます(Docker内蔵のDNSによる名前解決)。

```
[ユーザー定義ネットワーク: my-net]

  ┌─────────┐        ┌─────────┐
  │  web    │───────▶│   db    │
  │(コンテナ)│  "db"   │(コンテナ)│
  └─────────┘  で到達  └─────────┘
```

デフォルトでは何も指定せず起動したコンテナは `bridge` という既定のネットワークに参加しますが、そこではコンテナ名による名前解決が効きません。そのため、複数コンテナを連携させる際は自分で `docker network create` して使うのが基本パターンです(これは次章のDocker Composeが内部的に自動でやってくれる処理でもあります)。

## ハンズオン手順

`exercises/05-networking/` に移動します。

```bash
cd exercises/05-networking
```

ここでは、`web`(nginx)と`alpine`(通信確認用の軽量Linuxイメージ)の2つのコンテナを使って疎通確認をします。

### 1. まずはネットワークなしで失敗を体験する

```bash
docker run -d --name web nginx
docker run --rm alpine wget -qO- --timeout=3 http://web
```

`wget: can't connect to remote host ... Connection refused` のようなエラーになるはずです。これは、この2つのコンテナが同じユーザー定義ネットワークに属していないため、実際には`web`コンテナに到達できていないからです。

> **補足**: 同じコマンドを`ping -c 3 web`で試すと、環境によっては`127.0.53.53`という奇妙なIPに対して「成功」してしまうことがあります。これはDockerの内蔵DNSが「`web`という名前のコンテナはホスト上のどこかに存在するが、今の接続元からは到達できない」ことを示すための特殊なダミーアドレスです(`127.x.x.x`はどのコンテナから見ても必ず自分自身のループバックを指すため、`ping`は何にでも「成功」してしまいます)。そのため、この章では実際に到達できるかどうかを`wget`(HTTP通信)で確認するのが確実です。

### 2. ユーザー定義ネットワークを作成する

```bash
docker network create my-net
docker network ls
```

### 3. 同じネットワークに参加させて再実行する

一度既存のコンテナを片付けてから、ネットワークを指定して起動し直します。

```bash
docker rm -f web
docker run -d --name web --network my-net nginx
docker run --rm --network my-net alpine ping -c 3 web
```

今度は `web` という名前だけで正常に疎通できることを確認してください。

### 4. コンテナ内からHTTP通信もしてみる

```bash
docker run --rm --network my-net alpine wget -qO- http://web
```

nginxのウェルカムページのHTMLが取得できれば、名前解決だけでなくHTTP通信も成功しています。

### 5. ネットワーク詳細を確認する

```bash
docker network inspect my-net
```

`Containers`の項目に、参加しているコンテナとそのIPアドレスが表示されます。

### 6. 後片付け

```bash
docker rm -f web
docker network rm my-net
```

## 確認問題・やってみよう

1. なぜ手順1では`wget`が失敗し、手順4では成功したのか説明してみましょう。
2. `docker network inspect my-net` の出力から、`web`コンテナに割り当てられたIPアドレスを見つけてみましょう。
3. `-p`によるポート公開(ホスト↔コンテナ)と、ユーザー定義ネットワークによるコンテナ間通信(コンテナ↔コンテナ)は別の仕組みです。それぞれどんな場面で使うものか整理してみましょう。

## 詰まりやすいポイント・トラブルシューティング

- **`ping`だと失敗するはずの手順1で成功してしまう**: 上記の補足の通り、Dockerの内蔵DNSが返す`127.0.53.53`という特殊アドレスに対して`ping`は常に成功してしまいます。実際に疎通できているかは`wget`などHTTP通信で確認してください。
- **同じ名前のコンテナがすでに存在してエラーになる**: `docker rm -f web` で先に削除してから作り直してください。
- **`docker network rm`で`network has active endpoints`エラー**: そのネットワークを使っているコンテナがまだ存在します。`docker rm -f <コンテナ名>`で該当コンテナを削除してから再実行してください。
