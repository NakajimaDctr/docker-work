# 01. コンテナとイメージとは

## この章で学ぶこと

- 「コンテナ」と「イメージ」という2つの中心概念を区別できるようになる
- 仮想マシン(VM)とコンテナの違いを理解する
- `docker run` で実際にコンテナを起動し、その仕組みを体感する

## 概念解説

### イメージ(Image)とコンテナ(Container)

Dockerを理解する上で最も重要なのが、この2つの違いです。

- **イメージ**: アプリケーションを実行するために必要な、OSの一部・ライブラリ・設定・アプリコード等を1つにまとめた「読み取り専用のひな型」です。料理で言えば「レシピ」に近いものです。
- **コンテナ**: イメージを実際に実行した「動いているインスタンス」です。料理で言えば、レシピ(イメージ)をもとに実際に作った「一皿の料理」がコンテナです。

同じイメージから、何個でもコンテナを起動できます。コンテナは起動・停止・削除ができますが、イメージ自体は変化しません。

### 仮想マシン(VM)との違い

従来の仮想マシンは、ハードウェアをエミュレートし、その上に丸ごと1つのOS(カーネル含む)を起動します。そのため起動に数十秒〜数分かかり、ディスクサイズも大きくなりがちです。

一方コンテナは、ホストOSの **カーネルを共有** しつつ、プロセスやファイルシステムを隔離する仕組み(Linuxのnamespaceやcgroupという機能)を使います。そのため:

- 起動が速い(数秒以内、数百ミリ秒のことも)
- イメージサイズが小さい(数MB〜数百MB程度で済むことが多い)
- 1台のマシンでより多くのコンテナを同時に動かせる

その代わり、コンテナはホストOSと同じ種類のカーネル(Linux)上で動くことが前提です。Mac/WindowsでDockerを使う場合、裏側で軽量なLinux仮想マシンが1つ動き、その上でコンテナが実行されています。

### イメージはレイヤー(層)構造

Dockerイメージは複数の「レイヤー」が積み重なってできています。例えば「Ubuntu + Pythonをインストール + アプリコードをコピー」という3レイヤーがあれば、共通のレイヤー(Ubuntu部分など)は複数のイメージ間で共有・再利用されます。これによりディスク容量やダウンロード時間が節約されます(この仕組みは03章のDockerfileで詳しく扱います)。

## ハンズオン手順

`exercises/01-hello-docker/` に移動して進めます。

```bash
cd exercises/01-hello-docker
```

### 1. イメージを取得する(pull)

```bash
docker pull nginx
```

`nginx`という名前のWebサーバーのイメージがDocker Hub(イメージの公開レジストリ)からダウンロードされます。

### 2. 取得したイメージの一覧を見る

```bash
docker images
```

`nginx` がリストに表示されるはずです。`IMAGE ID`や`SIZE`(サイズ)にも注目してみましょう。

### 3. イメージからコンテナを起動する

```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

- `-d`: バックグラウンドで実行(detached)
- `--name my-nginx`: コンテナに名前をつける
- `-p 8080:80`: ホストの8080番ポートをコンテナの80番ポートに繋ぐ

### 4. 動いているか確認する

```bash
docker ps
```

`my-nginx` が `Up` の状態で表示されていればOKです。ブラウザで `http://localhost:8080` を開くと、nginxのウェルカムページが表示されます。

### 5. 同じイメージからもう1つコンテナを起動してみる

```bash
docker run -d --name my-nginx-2 -p 8081:80 nginx
docker ps
```

1つのイメージから複数のコンテナ(`my-nginx` と `my-nginx-2`)が同時に動いていることを確認しましょう。`http://localhost:8081` も開いてみてください。

### 6. 後片付け

```bash
docker stop my-nginx my-nginx-2
docker rm my-nginx my-nginx-2
```

## 確認問題・やってみよう

1. 「イメージ」と「コンテナ」の違いを、自分の言葉で1〜2文で説明してみましょう。
2. なぜ同じ `nginx` イメージから複数のコンテナを起動できたのか説明してみましょう。
3. `docker run -d --name my-nginx-3 -p 8082:80 nginx` を実行し、`docker ps -a` で停止中のコンテナも含めて一覧表示してみましょう(`-a`をつけるとどう変わるか確認)。

## 詰まりやすいポイント・トラブルシューティング

- **`port is already allocated`**: 指定したホスト側ポート(例: 8080)がすでに他のプロセスやコンテナに使われています。`-p 8090:80`のように別の番号に変えて試してください。
- **`docker ps`に何も表示されない**: `docker ps`はデフォルトで「実行中」のコンテナのみ表示します。停止したコンテナも見たい場合は `docker ps -a` を使います。
- **ブラウザで表示されない**: コンテナが `Up` になっているか `docker ps` で確認し、URLの `localhost:8080` のポート番号が `-p` で指定したホスト側ポートと一致しているか確認してください。
